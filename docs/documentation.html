What ClearTXT actively defends against, and why.

← Back to ClearTXT

Pasted text can carry more than what's on screen - characters with no visible glyph, formatting tricks that make text display in a different order than it's actually stored, and letters swapped for deceptive look-alikes from another alphabet. None of these need a human reader to fail to notice; they're just as effective against an AI assistant, a search index, or any other program that reads the raw text. Every fix below is on by default; turning one off in the "Fixes & explanation" panel leaves its characters exactly as pasted.

Hidden & invisible characters

Governed by: Strip invisible & control characters

  • Zero-width characters. Characters like the zero-width space, zero-width joiner, and byte order mark render as nothing at all, but they're still real characters in the underlying text - a message that looks identical on screen can contain extra hidden characters a program will still process.
  • Bidirectional overrides ("Trojan Source," CVE-2021-42574). A small set of control characters can force part of the text to display right-to-left (or force the reading order back), making text or code visually read in a different order than the characters are actually stored in - e.g. disguising which part of a filename is really the extension, or making a malicious line look like a harmless comment.
  • Unicode Tag smuggling ("ASCII smuggling"). A whole block of invisible characters, originally meant for obsolete language tagging, can be freely combined to encode arbitrary hidden text - including full instructions - inside a message that looks completely blank at that spot.
  • Deprecated variation selectors. A second, less-known invisible channel with the same effect: no legitimate modern use, but freely combinable to hide text the same way.
  • Plain control characters, plus a couple of easy-to-miss individual characters (the soft hyphen, the Arabic letter mark) that don't fit neatly into any of the categories above but are just as invisible in normal rendering.

Detected by testing every character against Unicode's own "Format" (Cf) general category, rather than a hand-maintained list of known offenders - this stays complete as Unicode adds more such characters in the future, with no maintenance needed here.

Filenames get this same treatment, unconditionally: a file you export, download, or add in batch mode never has one of these characters in its own name - not just its text content - regardless of whether "Strip invisible & control characters" is on. A filename is a different context from the text in the boxes above; it becomes a real name in your OS's file listings and Save dialogs, where a right-to-left override could visually disguise the file's own extension.

Look-alike (homoglyph) characters

Governed by: Strip look-alike characters

Swapping a letter for a similar- or identical-looking one from another alphabet is a classic way to disguise a fake domain or brand name as the real one - a Greek "ο" standing in for the Latin "o" in gοogle.com, or a Cyrillic "а" standing in for the Latin "a" in pаypal.com. To a human eye they're indistinguishable in most fonts; to a computer they're completely different characters.

Rather than maintaining a table of which specific characters "look like" which Latin letters (Unicode's own confusables data runs to thousands of entries), this works the way browsers already defend against the same trick in web addresses: text is split into "words," and any word mixing a Latin letter with a letter from any other script has just that minority-script character flagged - not the whole word, and not a word written entirely in another language (an actual Greek or Russian sentence is left alone). This runs ahead of the dedicated Hebrew/Arabic/Cyrillic options below, so turning one of those off to keep genuine text in that script doesn't also let a character from it slip through when it's hiding inside an otherwise-Latin spoofed word.

Script confusion

Governed by: Strip Hebrew / Arabic / Cyrillic characters

Beyond look-alike letters mixed into Latin words, an entire message can be written in a script you weren't expecting - dedicated options remove Hebrew, Arabic, or Cyrillic text outright if that's not something you want to see, independent of everything else on this page. A handful of mathematical symbols that are visually built from Hebrew letters (like ℵ, used for aleph-null) are protected from being silently folded into actual Hebrew letters by Unicode normalization, so they're governed by the general symbol option instead of quietly disappearing as "Hebrew."

What this page doesn't cover

  • ClearTXT cleans characters, not meaning - it can strip a hidden instruction's invisible packaging, but it can't judge whether the visible text left behind is itself trying to manipulate you.
  • It's a text-cleaning tool, not a comprehensive security scanner, and every fix above can be turned off - nothing here applies to text you don't run through it, or to a fix you've disabled.
  • Everything happens entirely in your own browser - nothing you paste is uploaded, logged, or sent anywhere. See the README for the full privacy picture.
